# Paseo UI／UX 交互规格

本规格替代此前新增控制面功能的提案。范围是既有消息、工具、推理、外观与基础交互的优化，不建立新的产品页面或执行流程。候选实现和证据见[验证记录](../../packages/paseo-codex-theme/VALIDATION.md)。

## 保留原生路径

用户仍在原生 workspace 打开 session、通过原生 composer 输入、使用原生权限／运行控件、查看原生文件／diff／终端并继续回复。本插件只改变受支持内容的呈现和已有展示交互。

不注册工作概览 screen、业务 sidebar item、证据 panel、业务 composer pill 或新的 slash command。设置放进已有 Settings → Plugins；可提供合成内容预览，但不变成工作台。

## 正文

- 优先系统字体，正文目标 14–16px；行高、段落间距和阅读宽度可调。代码使用等宽字体，长行可滚动或在明确偏好下换行。
- 标题、列表、引用、代码块与链接保持原始内容及顺序。复制使用完整原文，不只复制可见截断部分。
- 只对验证过的内容形态启用 renderer。富附件、媒体和未知类型不认领；不能为改善样式而丢弃信息。
- 不改写持久消息、不总结正文、不新增完成判断或渲染器之外的历史存储。

## 工具与推理

- 将现有工具名称、命令／输入摘要与原始状态组织成紧凑行。摘要是确定性的截断或已有字段，不额外调用模型。
- 支持用户展开原始参数、输出与错误；失败时错误入口始终可见。纯展示的折叠与展开不触发工具调用。
- 不将多个独立条目伪造为新的执行阶段；如宿主已有分组则尊重其语义。
- 默认保留原生工具分组。逐条工具样式会使匹配记录脱离原生命令聚合，因此只在用户明确开启后注册工具 transformer。
- 对原本可见的推理内容只调整呈现与展开方式，不将其当作可靠的结果证据，也不生成额外解释。
- 保持 source identity，流式更新不重置展开状态。长输出和长历史需限制额外渲染开销。

## 操作与响应式

复制、选择、链接、代码滚动、展开、键盘焦点、输入法与减少动态效果为必验项。相同控件在宽窄窗保持语义；不截断关键状态和错误原因。装饰图标不能抢占可访问名称。

不绑定新的全局快捷键、不代替原生发送、不改变回车／排队／转向／取消语义。用户阅读旧消息时，新增输出不应由本插件强制滚动或抢焦点。

## Composer 与外壳候选

公开主题 API 提供配色，不等于拥有全局字号、原生侧栏行高或 composer 布局。原生外壳缺少对应公开扩展点的部分不列入首版稳定能力。

如后续验证局部 desktop／web 样式适配，只允许作用于识别过的区域，默认关闭；不搬移原生控件、不替换事件、不修改内部 store。失配即保持原生，清理只撤销仍由本插件拥有的改动。原生移动端保持原生外壳。

## 设置与实现

| 层 | 实现入口 | 范围 |
| --- | --- | --- |
| 配色 | `addTheme` | 现有浅深色主题和可调 token，不自动切换当前主题 |
| 消息展示 | timeline transformer／renderer | 同步确定性处理，受支持内容才认领；按类型独立开关 |
| 偏好 | `addSettingsScreen`、公开 settings API | 字号、密度、折叠、显示开关与合成预览 |
| 可选适配 | 经验证的局部样式模块 | 默认关闭，与公开接口层分离，不能成为基础阅读依赖 |

候选包含工具／推理样式和经内容完整性验证的常见 Markdown／代码。正文流式阶段保持原生，完成后再决定是否认领。不给不支持的内容提供空替换。服务器仅注册公开外观偏好存储；不加入 Git／文件读取 RPC、生命周期自动化或执行控制。

公开接口依据：[plugin reference](https://paseo.sh/docs/plugins/reference)、[v0.11.4 类型](https://github.com/getpaseo/paseo/blob/dc5b02f7d7c120baea380d76def8b968020d8823/packages/plugin/src/client/contracts.ts)。共存及升级边界见 [兼容合同](compatibility-contract.md)。

## 验收

1. 相同内容和任务在原生与增强模式下对照，确认信息完整和原有操作可达。
2. 覆盖 Markdown、长代码、富附件、未知工具、失败输出、历史分页与流式更新。
3. 检查复制／选择／查找／链接、焦点／输入法、宽窄窗和浅深色。夹具不能代替真实 Paseo。
4. 各类增强可单独关闭；默认与可选样式适配分开验证。关闭、重载或断线后无资源和样式残留。
5. 按准确 App／daemon／SDK 版本和共存插件版本验收。未通过的格式或模块保留原生，不写进支持承诺。
6. 发布素材使用运行截图；概念图、类型检查、插件 running 状态与真实 UI 验收分别记录。
