# 既有体验的改造清单

用户已限定为 UI／UX 变更。设计目标是改善现有会话的阅读、重点发现与操作反馈；不新增工作台、聚合服务、执行逻辑或交付管理。以下是待验证的改造目标，不是已经复现的 Paseo 缺陷清单。

| 改造点 | 具体表现 | 验收方式 |
| --- | --- | --- |
| 内容层级 | 正文、标题、列表、引用、路径和代码有一致字号与间距；减少重复边框 | 同一段原始内容完整可读；长文、中文、代码与窄窗不溢出 |
| 工具密度 | 工具名、简短命令与现有状态形成紧凑行；细节按需展开 | 参数、输出与错误可找到；失败不会被折叠状态掩盖 |
| 流式稳定性 | 更新同一条消息时保留组件身份与展开状态 | 不丢焦点／选择；不因局部更新强迫用户回到底部 |
| 操作反馈 | 现有复制、链接、展开等动作有清楚的可访问名称和反馈 | 键盘、触控、指针与输入法行为正确；没有新增执行动作 |
| 外观与密度偏好 | token、字号和紧凑程度可调，浅深色共用相同结构 | 切换主题仍可读；不暗中改变 provider、权限或其他应用设置 |
| 输入区候选 | 仅研究现有控件的间距和对齐，保留原生事件及功能 | 先证明确切版本可用；结构变化或不支持的平台直接保持原生 |

成熟 AI App 的可借鉴点是内容优先、逐步展开、稳定反馈和输入语义清晰，而非复制整个产品功能或配色。参考 [Codex prompting](https://learn.chatgpt.com/docs/prompting#steering-and-queuing) 和 [VS Code 的审阅与控制说明](https://code.visualstudio.com/learn/foundations/reviewing-and-controlling-agent-changes)。这些资料不证明本插件已经提升效率。

社区 [Chat Skins](https://paseo.sh/plugins/devserra/chat-skins) 展示了可选消息样式与受限 composer 适配；[Chat Polish](https://paseo.sh/plugins/lthieu96/chat-polish) 展示了工具与富文本定制，同时明确了内部 DOM 依赖。这里只借鉴呈现模式，不引入其附带的总结、媒体读取或新业务功能；也不把内部结构当成公开合同。

## 判断 UI／UX 与功能扩张

同一内容更易阅读、已有细节更易展开、原有按钮更容易发现，属于本轮范围。新增“需要我处理”聚合、新的任务完成规则、解析测试结果形成证据状态、读取 Git 生成报告、自动重试／批准，属于功能扩张，均不纳入本插件。

关闭增强后，原生消息与业务行为应仍然完整。跨 host 只遵循当前会话已有上下文，不建立新的聚合视图或后台全量订阅。

## 实际组件原型

已用真实呈现组件和合成会话覆盖正文含代码、工具运行与失败、思考折叠、关闭增强及错误反馈。夹具进入仓库统一构建与服务入口；[截图与边界](evidence/ui/manifest.json) 明确使用了哪些模拟 host API。

原生会话已有工具聚合，因此逐条工具样式设为可选，默认保留分组。正文只在完成且受支持时改造；原生侧栏、composer、业务动作与媒体内容保持原有归属。
